### PWA・完全オフライン・安全な更新(2026-08-30)

- `manifest.webmanifest` と `sw.js` を追加。公開HTML・JS・CSS・内蔵画像など約13MBを初回に事前キャッシュする
- `tools/build-pwa.mjs` が公開対象を走査して `pwa-build.js` を生成。GitHub ActionsではコミットSHAを版IDにするため、デプロイごとに必ずService Worker更新が検出される
- 新版は別キャッシュへ全ファイルを保存し、完了するまで旧版を維持する。失敗時は壊れた新版へ切り替えない
- オンライン時はネットワーク優先、オフライン時は同一版キャッシュへフォールバック。HTMLと古い静的ファイルの混在を避ける
- 新版が待機状態になると全画面共通の更新帯を表示。自動再読み込みはせず、「最新版に更新」を押したときだけ切り替える
- `取り込み・設定` に「オフライン・更新」と「最新版を確認」を追加。Cache Storageだけを更新し、IndexedDBの園児イラスト・声・設定・ランキングは触らない
- ローカルで版IDを変えて更新検出→ボタン切替→1回再読み込みを確認。HTTPサーバー停止後もトップ・取り込み設定・かけっこが起動し、コンソールエラーなし
- iPad実機では、Safariからホーム画面へ追加した後、そのホーム画面版の中でデータを準備し、前日に機内モードでコールドスタート確認する

## 2. アプリ化について(検討済み・未着手)

### 結論

**Web を正とし、アプリはガワ(WKWebView か Capacitor)にする。** 今の HTML をそのまま同梱すれば、同じコードで iOS・Android の両方を出せる。

オーナーは Mac・Xcode・Apple Developer Program を持っているため、コスト面の障害はない。

### アプリでしか取れない利点

| 項目 | ブラウザ + ホーム画面追加 | ネイティブアプリ |
|---|---|---|
| 他の人・別端末への配布 | 「Safariで開いて→共有→ホーム画面に追加」を毎回説明する必要がある | App Store で「入手」を押すだけ |
| 横画面の強制 | **iPad Safari では不可**(ページから画面を回せない) | `Info.plist` で横向き固定。確実 |
| 販売・課金 | 不可 | StoreKit で完結 |
| オフライン | Service Worker のキャッシュ次第(事前に一度オンラインで開く必要あり) | インストール時点で同梱、依存ゼロ |

とくに「全画面ボタンで自動的に横画面」は iPad Safari ではどう書いても実現できない。今は代わりに、縦画面のとき「よこむきに すると 大きく 見えるよ」の帯を出している(`js/core.js` の `Rotate`)。

### 進めるときの注意

- **ガイドライン4.2(最低限の機能性)** … 単なる Web サイトのラッパーは弾かれることがある。「コンテンツを同梱して完全オフラインで動く」は有効な反論材料
- **キッズカテゴリ** … third-party 解析・広告は不可、外部リンクにはペアレンタルゲート、プライバシーポリシー必須。このアプリは通信を一切しないので書きやすい
- **データは移行されない** … ブラウザの IndexedDB とアプリ内ストレージは別物。本番で使う写真・クイズは「使うほうで」作るか、`admin.html` の zip 書き出し/読み込みで移す
- **イベント当日の必須条件ではない** … 当日は今の Web 版 + 画面の向きロック + アクセスガイドで戦える。アプリは配布・販売を見据えた別プロジェクトとして進めるのが安全

### 検証のやり方(Playwright)

実機がないので、Chromium をタッチありで動かして確認している。

```js
chromium.launch({
  executablePath: '/opt/pw-browsers/chromium-1194/chrome-linux/chrome',
  args: ['--no-sandbox', '--disable-gpu'],   // --no-sandbox が無いとハングする
});
browser.newContext({ viewport: {...}, hasTouch: true, isMobile: true });
```

よく使うサイズ:

| サイズ | 何 |
|---|---|
| 1194x834 | iPad 横(本番) |
| 834x1194 | iPad 縦 |
| 740x360 | スマホ横 |
| 393x800 | スマホ縦 |

はまりどころ:

- `--no-sandbox` を付けないとブラウザ起動でハングする
- node の stdout をパイプに流すとバッファされて途中経過が見えない。**ログはファイルに書く**
- ページを開いた直後はサンプル画像の生成が重い。**2秒ほど待ってから**操作する
- レイアウトの重なりは目視より `elementFromPoint` で測るほうが速い(PR #30 の戻るボタンはこれで原因が分かった)
